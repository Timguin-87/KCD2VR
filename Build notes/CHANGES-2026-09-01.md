# 2026-09-01 architecture revision

* Defaulted to tracking-only OpenXR operation (`DiagnosticRendering=false`).
* Fixed D3D12 command-queue capture to accept DIRECT queues only.
* Corrected camera hook order: HMD transform is applied before the original frustum builder.
* Camera pose now composes with KCD2's untouched CView position/orientation rather than replacing it.
* Added initial recenter origin and controller recenter action handling.
* Made positional tracking local to the current KCD2 view basis.
* Avoided same-frame translation accumulation by rebuilding from untouched CView fields each call.
* Added independent rotation/position debug toggles.
* Added a conservative WHGame-module vtable sanity gate; full CView RTTI validation remains TODO.
* Rewrote ROADMAP.md and added FORUM_POST_NOTES.md.

## Adapter/recenter correction pass

- Fixed the OpenXR adapter compatibility check to use `ID3D12Device::GetAdapterLuid()` directly. The previous `ID3D12Device -> IDXGIDevice` `QueryInterface` was invalid for D3D12 and produced `E_NOINTERFACE (0x80004002)` even on a valid GPU.
- Adapter mismatch logging now includes both the KCD2 and OpenXR LUID values.
- Recenter (X/A) is now edge-triggered using `XrActionStateBoolean::changedSinceLastSync`, preventing a held button from recentering every XR frame.
- Clarified the roadmap: diagnostic command-list/fence synchronization is internal only; render-thread synchronization with KCD2 is still TODO and `DiagnosticRendering=true` should remain disabled until it is restored.
- Preserved the C2712-safe camera pose snapshot structure (`std::lock_guard` stays outside the SEH detour function).


## Diagnostic logging pass

- Added `KCD2VR-debug.log`, a crash/debug-friendly fallback trace that flushes every line to disk immediately.
- Added sparse runtime counters for OpenXR frames, valid HMD poses, and camera-pose applications.
- Added explicit trace milestones for hook install, D3D12 capture, OpenXR initialization, tracking-only mode, first HMD pose, and first camera application.
- `DiagnosticRendering=false` remains the default; this build still does not intentionally submit custom D3D12 eye images in the safe test configuration.

## Render-thread / native-stereo foundation

- Restored a producer/consumer handoff for custom D3D12 work.
- Hooks the captured DIRECT queue's `ExecuteCommandLists` and uses that thread as the D3D12 submission rendezvous.
- Keeps `xrWaitFrame`, tracking, swapchain acquire/wait/release, and `xrEndFrame` on the XR worker thread.
- Uses the original `ExecuteCommandLists` entry point for KCD2VR submissions to avoid recursive hook entry.
- Adds shutdown quiescence: callbacks are disabled and drained before OpenXR/D3D12 objects are destroyed.
- Publishes a thread-safe stereo snapshot containing OpenXR's predicted display time, exact left/right `XrPosef`, and asymmetric `XrFovf` values.
- Does **not** yet render KCD2 twice. Native scene stereo still requires identification of the game's main-view render dispatch and safe per-eye temporal handling.
- Runtime milestone from the latest tracking-only test: positional and rotational 6DOF drove the KCD2 desktop view without the earlier purple-screen crash.


## Live diagnostics path fix
- `KCD2VR-debug.log` is anchored to the loaded ASI directory instead of the process current working directory.
- Every fallback line includes a sequence number and Windows thread ID and is mirrored to `OutputDebugStringA`.
- `DiagnosticRendering=false` remains the default; synchronized purple-eye submission is opt-in only.


## ASI-relative config loading fix
- `KCD2VR.ini` is now resolved beside the actually loaded `KCD2VR.asi`.
- Startup diagnostics print the exact INI path used.
- Startup diagnostics print the parsed values for `Enabled`, head rotation/position, `DiagnosticRendering`, and `HeadPoseScale`.
- This addresses runtime tests where an uploaded INI contained `DiagnosticRendering=true` but the mod still entered tracking-only mode.


## DiagnosticRendering boolean parser fix
- Runtime proved the correct ASI-relative INI was loaded but DetourModKit's bool binding still produced `false` for `DiagnosticRendering = true`.
- `DiagnosticRendering` is now explicitly re-read with the Win32 INI API and accepts `true`, `1`, `yes`, or `on` case-insensitively.
- The raw value and parsed boolean are written to `KCD2VR-debug.log` before OpenXR initialization.
