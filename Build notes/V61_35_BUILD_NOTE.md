# KCD2VR V61.35 build note — calibration + generic depth + final-output VRIK ownership proof

Base: V61.34 calibration/depth-probe source.

This build keeps the V61.34 old calibration menu, corrected F8 mono/pseudo projection, inverted HUD scale test, and generic F4 depth observer. It adds one new F9 VRIK ownership experiment at the post-animation final skinning transform output.

## F9 state machine

F9 cycles:

1. OFF -> READ
2. READ -> READ+WRITE
3. READ+WRITE -> OFF

READ is strictly observational. It correlates the final-skinning job with Henry using the already-proven CPoseData identity anchor, then reads the final 0x20-byte-per-joint skinning output slots for the two live WeaponSolver joint IDs. No CPoseData setter is called.

READ+WRITE uses the same correlation, but writes only the final transform output generated by `WHGame+0x5FE2F0`, after normal animation/CPoseData processing has already completed. The old CPoseData/OperatorQueue/final-consumer pulse is not used.

## Static basis for the new final-output target

Disassembly of the supplied `WHGame(6).dll` shows `WHGame+0x5FE260` building a small descriptor and calling `WHGame+0x5FE2F0`. Inside `+0x5FE2F0`:

- descriptor `+0x00` is the outer arg5 used in prior runtime sessions to correlate Henry's proven CPoseData;
- descriptor `+0x08` is the joint/skeleton owner used by a virtual joint-count getter;
- descriptor `+0x20` is loaded as the output pointer;
- output advances by `0x20` bytes per joint;
- the transform builder writes two four-float halves for each joint before the outer final-skinning function resumes.

The V61.35 write probe fails closed unless one half of the 0x20 slot looks like an approximately unit quaternion. It changes only the other half with a small vector mathematically orthogonal to the real quaternion, i.e. a dual-quaternion translation-tangent perturbation, and leaves rotation data untouched. The test amplitude is intentionally small (~5 cm class). Normal animation rebuilds the output on the next skinning update.

This is an ownership proof, not finished VRIK. If the visible hand/weapon finally responds, the next stage is to replace the oscillating proof with the already-designed controller-driven two-bone arm solution from V49 at this late output boundary.

## Retired paths remain retired

- no OperatorQueue pose writes;
- no CPoseData setter writes from F9;
- no larger V61.30 final-consumer hand pulse;
- no semantic FULLBODY table write;
- no native stereo resurrection;
- V61.12 gameplay-only culling unchanged.

Source/static validation only. No Windows/MSVC or headset runtime verification was possible here.


## F4 depth-push merge + compile repair

This fixed package also merges the user-supplied V61.35 depth-push changes into the final-output/F9 branch. F4 still enables the generic D3D12 DSV/draw candidate observer, but while F4 is ON the compositor can consume the current best candidate once it has at least 200 observed draws and matches the captured screen resolution/aspect. The depth signal only modulates the already-existing pseudo-stereo horizontal shift; it does not perform full reprojection. Default signed modulation weight is 0.20 and the shader clamps the effect. If no trusted depth resource exists yet, the effective weight is exactly zero and presentation falls back to the prior pseudo path.

The user-reported MSVC compile failure in `mod.cpp` is repaired. V61.34 deliberately made game FOV and source/view FOV user-owned while F8 is active, but stale V61.32 logging/shutdown references to `f8_restore_game_fov` and `f8_restore_source_fov` remained. Those nonexistent identifiers are removed. F8 now saves/restores only `f8_restore_center_y`; it neither restores nor overwrites user game/source FOV at shutdown. The malformed/stale `snprintf` argument set is replaced accordingly.

The F4 depth-push merge does not replace the F9 final-output ownership test. Both tests coexist in this build.
