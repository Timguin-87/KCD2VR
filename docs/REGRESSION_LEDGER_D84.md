# D84 regression ledger and next-owner handoff

This ledger records why a change is retained and what would actually close the remaining question. It is not a list of features already verified in a headset. Source marker: `KCD2VR-D84-REGRESSION-REPAIR-20261102`.

## Remaining implementation work and evidence needed

**Paired combat:** identify the real native paired damage/event owner, its cancellable state and the mapping between the current VR blade edge/contact and the paired target. Define exactly which native event waits for contact without double damage or breaking progression. Until then native paired timing stays 1x. F3 now reveals the first pair-read refusal and explicitly labels contact-event authority unproven.

**Dice cup:** qualify the exact cup attachment and controlling native action over take, shake and placement. A physical experiment needs one hand owner, a valid manipulation interval, coherent cup/world transforms and a native throw-completion contract. Separately join each visible die to the native index, then acknowledge actual keep/unkeep state before presenting success. F5 observes current native action map/cursor; F7 observes the existing body/native pose. The cup's default nonphysical script and empty generic action list must not be mistaken for a ready-made grab API.

**Corpse movement:** use F9 with the selected corpse feature and an empty hand. The meaningful chain is provider callback age, native dead candidate, raw grip consumed, current body/anchor, native movement request, measured body movement and release. A living-root refusal is not solved by bypassing the death check. The current saved route is a whole-body servo, not a limb constraint. A new physics mechanism needs an actual validated native contract.

**Physical crossbows:** F5 and F7 now reach the real reload/pose/binding producers together; F11 is optional compatibility. Check direct pull, tool retrieval, actual hand placement, socket engagement, lever travel, native cock acknowledgement, shoulder bolt retrieval, actual bolt hand pose, nocking and native load acknowledgement. Missing or mismatched evidence must retire the physical owner with its real reason. Do not add a second reload owner or unconditionally accelerate across physical markers.

**General props and both hands:** the ordinary item system supports either acquiring hand sequentially. Simultaneously holding two unrelated props needs independent owners and release/physics lifetimes. Decorative scenery needs a validated world-prop contract independent of inventory. Neither feature is obtained by broadening inventory eligibility to every render mesh.

**Alchemy sound/particles and every collision mode:** retain the current semantic/readback/cue chain and contact continuity. Existing records do not prove audible output or rendered particles. Compare actual native cue dispatch, emitter/attachment identity and observable result. Sparse hand contact coverage remains an implementation limit.

**Performance and stereo:** keep the accepted hand timing and the reviewed separate-eye DLSS/FSR bridge. D84 removes automatic map profiling and guards specific diagnostic reads. Compare matched scene/configuration, refresh policy, CPU/GPU/frame submission and diagnostic state before attributing the remaining 90/110 FPS difference. H50/D52 were the same scene. No D84 FPS or vendor GPU result exists here.

## What is preserved

Current runtime INI/calibration; native bow aim/shoot; accepted Fresh Pose smoothing; camera/projection, frame scheduling and XR submission; reviewed DLSS/FSR context and composition code; D81 collision corrections; current mortar/native work semantics; continuous physical reload ownership; native inventory/combat/recipe outcomes. Throwing knives remain retired. Native mounting completes, then the existing normal VRIK path starts one second later, including unarmed riding.

The patch includes a protected-source hash receipt and exact installer/full-tree verification. Shared Mod and pose-host files necessarily contain the small documented integration changes; their presence in a diff does not imply the renderer or bow algorithm changed.
